# 核心交互修复：v0.6.5-recovery.2

这是前一版本的历史记录。当前数值候选为 v0.6.6-balance.1，变化见 [BALANCE_CHANGES.md](BALANCE_CHANGES.md)；下面的“数值未调整”和测试计数仅指 recovery.2。

本轮先修规则、预览与触发时序。骨钉每次命中获取 11 灵魂、常规法术消耗 33 灵魂、灵魂上限 99，以及卡牌伤害、能量费用、升级值和伙伴生命数值均未调整。

## 修复内容

| 交互 | 原行为 | 当前行为 |
| --- | --- | --- |
| 重放与免费自动出牌 | BaseLib 的旧付款被重复计入，耗魂抽牌、魂丝哺育等可能凭空触发 | 只记录本次真实付款；首段绑定一次，后续重放不会复用。先付款再自动打出的合法情况仍记账 |
| 盈满之魂 | 从当前灵魂与旧付款反推 66 阈值，可能误判 | 保存真实付款前的灵魂快照；无付款的重放和自动打出使用其当前灵魂 |
| 灵魂图腾、溢魂斩 | 自动打出或重放绕过普通可打出检查，灵魂不足仍可能生效 | 执行时再次检查 33 门槛；不足时不产生需要这笔付款的效果，也不虚报消费 |
| 溢魂斩、魂壳涌现 | 结尾只减去开头快照，期间产魂可能残留 | 伤害或格挡按开头魂量计算，结尾清空当刻真实魂量，记录实际消费 |
| 影披风 | 伤害预览会设置待闪避状态并闪烁，可能误消耗 | 预览不修改状态；真实伤害修改通知才启动后续消耗 |
| 暗影祠 | 预览漏显示加伤，附加伤害的限制不完整 | 预览与实际己方法术攻击加伤一致；无加成属性的固定副伤害保持固定。中英文状态说明补齐“本回合” |
| 法术副伤害来源 | 暗影之魂溅射、黑暗降临穿透伤害缺少卡牌来源 | 保留伤害值和属性，补齐卡牌与施放来源，使灵魂暴君击杀等能够正确归因；灵魂虹吸同样补齐来源 |

付款在资源钩子结束后记录，在出牌流程入口预留到独立作用域，避免同一卡牌被嵌套自动打出时抢走外层付款。成功、异常、取消及零次播放都会结束自己的作用域；跨战斗的付款被丢弃。

## 保留的伙伴规则

已对照当前游戏的实际伤害流程审查：先扣玩家格挡，随后一只伙伴承受未格挡的敌方攻击，优先孵化小虫、织者幼虫、格林之子。单次攻击超过该伙伴生命的部分回到玩家，不继续分摊给第二只伙伴。

重复召唤仍复用存活同种并增加当前和最大生命；格林成熟最多两次。指令多段逐段计数，群攻计一次，回合末自动攻击不计指令，玩家回合开始清零。宠物死亡移除与战斗结束清理由游戏负责。本轮没有重写这些已符合说明的行为。

## 自动验证

`tests/` 直接调用本工程、游戏和 BaseLib 的真实 DLL 方法。32 组、98 个断言通过，覆盖伤害预览、付款、门槛、重放、自动打出、作用域、伙伴承伤选择及实际 Harmony 分派。运行方式见 `tests/README.md`；逐项结果见 `validation/core-interaction-tests.json`。原恢复版首批 11 组中的 5 个失败单独保存在 `validation/core-interaction-baseline.json`，用于复现预览问题；新增付款用例没有完整的修复前对照。

这套测试没有运行游戏主场景，也没有使用玩家存档。它验证规则和钩子，完整伤害命令的动画、回合调度、联机与保存继续仍需游戏内验收。

## 游戏内验收

使用 `dist/HollowKnight/` 的四个文件，在独立测试存档中确认模组列表版本为 `v0.6.5-recovery.2`。

1. 0、32、33、66、99 灵魂下测试普通法术、图腾、溢魂斩。不足 33 的图腾或溢魂斩被自动打出时，不应产生需付款的效果。
2. 66 灵魂支付 33 的法术重放一次：消费记录总计 33；首段满足盈满之魂，第二段若只剩 33 则不满足。随后免费自动打出同卡，不应继承旧付款。
3. 装备魂之回响、灵魂图腾遗物、魂丝哺育，检查上述重放不会重复触发消费收益；真实预付款的自动出牌仍可触发。
4. 溢魂斩命中反伤敌人并触发受伤产魂：伤害按开头魂量计算，结尾灵魂为 0。
5. 影披风生效时反复查看伤害预览；下一次攻击若被格挡完全吸收，应保留影披风；下一段实际穿透格挡的伤害才消耗它。
6. 暗影祠之后查看法术预览，核对实际伤害；多段法术各段享受加伤，固定副伤害不加。未使用的神龛祝福在本回合结束时消失。
7. 用暗影之魂的溅射或黑暗降临的穿透伤害击杀，检查灵魂暴君的能量、抽牌与每回合两次上限。
8. 玩家 5 格挡、孵化小虫 4 生命并有另外两只伙伴时承受 12 攻击：格挡损失 5、小虫承受 4、玩家损失 3，另外两只伙伴不掉血。
9. 同种重复召唤、伙伴死亡后重召、多段指令、群攻及回合末自动攻击，检查数量、生命与指令计数；战斗结束后进入下一战。
10. 保存并继续；若使用联机，双方分别验证伙伴、灵魂与伤害结果一致。
